# Primeros 30 minutos desde el GO

Este es un presupuesto de tiempo adaptable, no la agenda oficial ni permiso para saltarse prerrequisitos. Si un acceso falla, registrar el bloqueo y pedir ayuda; no consumir intentos ni cambiar de cuenta al azar.

| Minutos | P1 | P2 | P3 | P4 |
|---|---|---|---|---|
| 0–5 | Aceptar invitación solo al GO; verificar cuenta/tenant/suscripción/RG | Confirmar acceso repo backend y versión | Confirmar repo frontend y scripts | Reglas finales, permiso IA/datos/GitHub, límites Azure, CTFd, dueños |
| 5–10 | Leer IaC/procedimiento entregado y recursos existentes | Leer README, entrypoint, settings esperados | Leer build/config y URL esperada | Leer narrativa y pregunta activa; abrir bitácora |
| 10–15 | Preparar despliegue indicado con alcance para aprobación | Inventariar rutas reales/contrato/pruebas | Preparar captura Network/Console | Verificar asignación y una sola operación cloud |
| 15–20 | Si aprobado, procedimiento oficial; capturar estado y errores | Analizar primer stack si ya existe | Reproducir flujo solo si entorno disponible | Registrar versión, horas y experimento actual |
| 20–25 | Consultar Failures/KQL o logs de arranque | Correlacionar primera línea propia y dependencia | Comparar URL, request y respuesta | Elegir hipótesis prioritaria y revisar evidencia |
| 25–30 | Preparar o ejecutar fix aprobado si justificado | Prueba dirigida y revisión | Validación navegador | Registrar resultado; borrador CTFd solo con evidencia |

- [ ] Cuatro integrantes presentes, dispositivos conforme a mentor; ningún chat prohibido abierto.
- [ ] Dos accesos Azure como máximo, un operador, ámbito correcto.
- [ ] Repos/commits/versiones/endpoints reales inventariados, sin asumir los del workshop.
- [ ] Evidencia inicial antes de corregir, UTC y Panamá documentados.
- [ ] Un dueño por archivo/hipótesis y una sola operación cloud.
- [ ] Ningún envío oficial ni despliegue sin aprobación; ningún secreto en bitácora.

No es obligatorio cerrar E1 antes del minuto 30: el resultado útil es acceso correcto, primer incidente reproducido y experimento verificable.
